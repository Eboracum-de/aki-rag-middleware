# Project governance and lifecycle

Eboracum GmbH maintains the main SunaQ repository and decides which changes are accepted into the upstream branch.

This governance model is intentionally simple for the initial public phase. It does not restrict the rights granted by the AGPL: users and contributors remain free to fork and continue the software under the applicable license terms.

## Project states

The repository may use one of these maintenance states:

- **Active** — regular development and review.
- **Maintenance** — primarily security, compatibility and important bug fixes.
- **Archived** — upstream development has stopped; the repository is kept read-only as public history and as a stable reference for existing users and forks.

Before archiving, the maintainer should update the README, close or label remaining issues, publish the final known status and identify any active successor/fork if one exists.

Archiving is preferred to deleting the project merely because active development has ended.

## Contributions

See `CONTRIBUTING.md`. Substantial contributions are discussed before submission and use the project CLA so the rights chain remains clear for both the public AGPL project and possible separately negotiated commercial licenses. Contributors retain ownership.

## Support expectations

No SLA is currently offered. Tested baselines and known limitations are documented in the repository and release notes. Questions can be sent to `rag@eboracum.de`.
